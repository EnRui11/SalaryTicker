一款 macOS 菜单栏应用，显示你今天已经赚到多少钱，每秒跳一次。

<img src="docs/panel.png" width="360" alt="小窗口：今日已赚、背后的几项计薪费率、本月已累计，以及两个储蓄目标和它们各自的到手日期。">

它在菜单栏里就是一个数字加一个小进度环。点一下，能看到今天的明细、本月到目前为止的累计，以及离你攒钱想买的东西还差多远。

- **按秒跳动**，依据你真实的作息 —— 上下班时间、不计薪的午休、工作日。
- **认得各种休假。** 公众假期、带薪休和无薪休落在不同的地方，而无薪休只动基本薪资，不动津贴。
- **用工作量给东西标价。** 一个目标不只显示金额，还会显示它值多少个工作日，以及按作息推算的到手日期。
- **九种语言**，任意货币符号，任意 IANA 时区。
- **不用账号、不联网、不上报数据。** 一切都在你自己的 Mac 上，根据你填的设置算出来。

## 安装

需要 **macOS 14 或更高版本**，以及一套 Swift 6 工具链。构建和测试都基于 Swift 6.3；更早的 Swift 6 版本没有测过。

```bash
git clone https://github.com/EnRui11/SalaryTicker.git
cd SalaryTicker
./Packaging/build_app.sh install
```

这条命令会构建 release 版二进制、从源文件生成应用图标、组装出 `SalaryTicker.app`、做一次 ad-hoc 签名，然后把它拷进 `/Applications` 并启动。去掉 `install` 参数，就只在当前目录里构建，不安装。

没有什么隔离属性需要解除：二进制是你自己编译的，从来就没带上 Gatekeeper 要找的那个下载标记。签名是 ad-hoc 的，对本地构建的应用来说够用了，也让登录项有一个稳定的身份。

要更新，拉一下代码再跑同一条命令 —— 它会替换已安装的那份并重新启动。你的设置存在 app 包之外，不会被碰到。

卸载：在小窗口里点「退出」，删掉 `/Applications/SalaryTicker.app`；如果连设置也想清掉，就执行 `defaults delete com.steve.salaryticker`。

## 首次运行

菜单栏会一直显示 `设置薪资`，直到作息填得说得通为止。从小窗口打开**设置**，填三样东西：

1. **薪资标签页** —— 你的基本薪资，以及旁边那笔固定津贴（如果有）。
2. **作息标签页** —— 上班、下班，还有午休不计薪。
3. **薪资标签页里的「工作日」** —— 一周里哪几天上班，其中哪几天是半天。

<img src="docs/settings.png" width="420" alt="薪资标签页：基本薪资、津贴、当月工作日天数、推算时薪，以及用来标休假的月历。">

这样就够开始了。其余都是可选的。

## 详细设置

### 基本薪资与津贴

两个字段，因为一张工资单至少有两行，而休假对它们的处理并不一样：

- **基本薪资**是无薪假要从里面扣的那一部分。
- **津贴**是每月固定的一笔钱 —— 交通、电话之类 —— 不管你有没有请无薪假，都照发全额。

如果你没有津贴，留着零就行，什么都不会变。如果有，把两者分清楚，才不会让一天无薪假扣得比它实际该扣的多。

### 工作日、假期和休假

选出你上班的星期几，其中任何一天都可以标成**半天**（比如周六上午）—— 它在所有地方都按半天算。

点月历里的日期，它会循环切换：**工作日 → 带薪休 → 无薪休 → 工作日**。标题两侧的箭头用来翻月份，标题本身点一下就回到本月，所以明年的公众假期可以在到来之前先标好。

两种休假落在不同的地方，而这个差别正是重点所在：

|                  | 它的作用                                                                                                                                                                                  |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **带薪**休 | 不花你一分钱。同样的薪水现在摊在更少的工作日上，所以你*真正*上班的每一天都更值钱一点。假期当天本身一分不跳 —— 它那一份摊到了别的日子上。 |
| **无薪**休 | 扣掉一天的**基本薪资**。津贴照样全额到账。                                                                                                                                                      |

有一个后果值得知道：把一个**已经过去的**日子标成带薪休，会让本月已累计的数字掉下来，因为那天的份额现在得由后面还没到的日子去赚。到了月底，它还是会回到你的薪水上。

### 加班

默认关闭。打开之后，下班后会按你设定的倍率继续计薪。

它有**上限** —— 默认四小时，而且绝不跨过午夜 —— 因为程序根本不知道你实际几点离开。没有这个上限，一台整夜开着的 Mac 会凭空造出一整晚的工资。

### 目标

把你想攒钱买的东西加进来。每一项都会显示它值多少个**工作日**，以及按作息推算的到手日期。想看的可以显示在小窗口里，其余的留在设置里。

**上班时这个日期不会动。** 你赚到的钱和时钟走过的时间是同步推进的，所以照着作息上班只会兑现这个承诺，而不会把它往后推。唯一能挪动它的，是改动底下的作息 —— 标一天休假、去掉一个工作日、缩短上班时长。

### 菜单栏

| 选项                          | 它的作用                                                                           |
| ------------------------------- | -------------------------------------------------------------------------------------- |
| 进度环                   | 数字旁边的一个小环，随着一天推进慢慢填满                                                |
| 货币符号                 | 显示或隐藏，省回一个字符的宽度                                                      |
| 非工作时段只显示图标 | 数字不动的时候把这一项收起来 —— 晚上、周末、上班之前 |
| **隐藏金额**                 | 不管时钟走到哪里，都把钱从菜单栏拿掉，直到你要它回来 |

**隐藏金额**也是小窗口里的第一项，从菜单栏点一下就到 —— 会议要开始了，或者有人从你背后看屏幕的时候用得上。它不会把*所有东西*都藏起来 —— 进度环还留着，否则就没有东西可点，也就没法把数字叫回来了。

### 开机自动启动

需要应用从 `/Applications` 里运行。存下来的是你的意愿本身：开关打开时，应用每次启动都会把自己注册一遍，而且从不注销 —— 因为菜单栏应用只要跑过一次，macOS 就会把它列进登录项，它给的答案两个方向都信不过。

## 这个数字是怎么算出来的

```
basic per day     = basic salary ÷ (scheduled days − paid leave)
allowance per day = allowance    ÷ (scheduled days − all leave)
per second        = (basic per day + allowance per day) ÷ paid seconds per day
today             = paid seconds elapsed today × per second
this month        = days already earned × daily pay + today
```

两个除数都按**真实的日历月份**来数，所以一个满勤的月份加起来正好是你的薪水，日薪则会随月份小幅浮动 —— 2026 年 8 月有 21 个工作日，9 月有 22 个，2027 年 2 月有 20 个。

每日计薪时长由上班、下班和午休算出来。没有单独的「每日小时数」字段，所以两者永远不会互相矛盾。

### 它不会走偏

每次刷新都从 `(settings, now)` 重新算一遍，**不累加任何东西**。合上盖子、睡眠、退出再打开、改系统时钟、飞过好几个时区 —— 这些都不可能让数字出错，因为根本不存在一个会出错的累计值。

定时器只负责说一句「该重画了」。它不计数，而且只要数字是静止的，它就放慢到 20 秒打一次盹 —— 大多数晚上和每个周末都是这样。

### 没有暂停键，是故意的

这个数在计薪时段的两端都会饱和：工作日开始前的那一瞬值零，结束后的那一瞬值满勤一天。所以数字**下班后自己停，午夜自己归零** —— 没有定时器要停，也没有状态要重置。

手动暂停确实短暂存在过。它是应用里唯一一处累计状态，也是它两个最严重的 bug 的来源：一次整夜没关的暂停，会扣掉超过一整个工作日，还把第二天清成零；而下班之后才开始的暂停，会让已经结算好的当日总额*倒着*跳。把这个功能删掉，也就把这一整类 bug 删掉了。

## 已知的局限

- **不支持跨夜班次。** 下班时间必须晚于上班时间；否则应用会显示「设置不完整」，而不是给你一个错的数字。
- **没有奖金。** 模型里只有每月固定的津贴。偶发的或年终的一笔钱，要出现在这里就得摊成每秒的数字，而那是在美化这个数字，不是在描述它。
- **不算税、EPF 或 SOCSO。** 所有数字都是税前的。
- **没有历史记录。** 本月已累计是从这个月的作息推算出来的，不是从一份实际出勤的记录里来的。改薪资或作息，会把当月已经过去的那些天重新定价。
- **只有一套作息。** 不是按周重复的模式 —— 隔周上的周六、轮班 —— 只能靠手动标出例外来表达。
