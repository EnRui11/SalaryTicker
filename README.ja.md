今日ここまでに稼いだ額を、1秒ごとに刻んで表示する macOS のメニューバーアプリ。

<img src="docs/panel.png" width="360" alt="パネル：本日の収入、その裏にある単価、今月の累計、そして達成予定日つきの貯金目標2件。">

メニューバーには、金額と小さな進捗リングとして常駐する。クリックすれば、その日の内訳、今月ここまでの累計、そして貯めているものにどこまで近づいたかが見られる。

- **1秒ごとに刻む。** 基準になるのは実際の勤務設定、つまり勤務時間、無給の休憩、勤務日。
- **休暇を知っている。** 祝日、有給休暇、無給休暇はそれぞれ別のところに効く。無給休暇が触るのは基本給だけで、手当には触れない。
- **値段を仕事の単位に直す。** 目標は金額だけでなく、営業日数と、勤務予定から算出した達成日で表示される。
- **9言語**対応。通貨記号は自由、IANA タイムゾーンも自由。
- **アカウントなし、通信なし、テレメトリなし。** 計算はすべて、自分で入力した設定をもとに、この Mac の中で行われる。

## インストール

**macOS 26 以降**と Swift 6 ツールチェーンが必要。ビルドとテストは Swift 6.3 で行っている。それより前の Swift 6 リリースは未検証。

```bash
git clone https://github.com/EnRui11/SalaryTicker.git
cd SalaryTicker
./Packaging/build_app.sh install
```

これでリリースビルドを作り、アプリアイコンをソースから生成し、`SalaryTicker.app` を組み立て、アドホック署名し、`/Applications` にコピーして起動する。`install` 引数を外せば、インストールせずに作業ディレクトリ内へビルドするだけになる。

隔離属性を外す作業は要らない。バイナリを自分でコンパイルしている以上、Gatekeeper が見るダウンロード済みフラグは最初から付かない。署名はアドホックだが、ローカルでビルドしたアプリにはそれで十分で、ログイン項目に安定した識別子を与える。

更新するときは pull して同じコマンドを実行するだけ。インストール済みのものを置き換えて起動し直す。設定はバンドルの外にあるので、そのまま残る。

アンインストールするには、パネルから終了し、`/Applications/SalaryTicker.app` を削除する。設定も消したければ `defaults delete com.steve.salaryticker`。

## 初回起動

勤務設定が成り立つまで、メニューバーには `給与を設定` と出る。パネルから**設定**を開き、次の3つを埋める。

1. **「給与」タブ** — 基本給と、あれば隣に固定の手当。
2. **「勤務時間」タブ** — 出勤、退勤、そして無給の休憩。
3. **「給与」タブの「勤務日」** — どの曜日に働くか、そのうちどれが半日か。

<img src="docs/settings.png" width="420" alt="「給与」タブ：基本給、手当、その月の勤務日数、そこから算出した時給換算、そして休暇を記入する月間カレンダー。">

始めるにはこれで十分。ほかはすべて任意。

## 設定する

### 基本給と手当

欄が2つあるのは、給与明細には最低でも2行あり、休暇の扱いもその2つで違うからだ。

- **基本給**は、無給休暇が差し引かれる側。
- **手当**は毎月固定の金額で、交通費や通信費のたぐい。無給休暇を取ったかどうかに関係なく全額支給される。

手当がなければ 0 のままでいい。何も変わらない。手当があるなら、2つを正しく分けておくことで、無給休暇1日が実際より高くつくのを防げる。

### 勤務日、祝日、休暇

働く曜日を選び、そのうちどれかを**半日**にする（たとえば土曜の午前だけ）。半日はどこで数えても半分として扱われる。

月間カレンダーの日付をクリックすると、**勤務日 → 有給休 → 無給休 → 勤務日**と切り替わる。見出しの両側にある矢印で月をめくれるし、見出し自体が今月に戻る手段になっている。だから来年の祝日も、来る前に入れておける。

2種類の休暇は別々のところに効き、その違いこそが要点になる。

|                | どうなるか                                                                                                                                    |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| **有給**休     | 何も損しない。同じ給与がより少ない勤務日に配られるので、実際に*働く*一日一日が少しだけ高くなる。休みの当日は何も刻まない。その取り分は他の日に乗る。 |
| **無給**休     | **基本給**が1日分減る。手当はそれでも全額届く。                                                                                                 |

知っておく価値のある帰結が一つある。**すでに過ぎた**日を有給休にすると、今月の累計は下がる。その日の取り分を、これから先の日で稼ぎ直すことになるからだ。月末には元どおり給与額に着地する。

### 残業

既定ではオフ。オンにすると、退勤を過ぎても、指定した割増率で計算を続ける。

ただし**上限**がある。既定で4時間、そして日付をまたぐことはない。アプリには実際に何時に帰ったのか分からないからだ。天井がなければ、一晩つけっぱなしの Mac が丸一晩分の給与を勝手に作り出してしまう。

### 目標

貯めているものを登録する。それぞれ、**営業日**で何日分かと、勤務予定から算出した達成日が表示される。見たいものだけパネルに表示しておけばいい。残りは設定の中に留まる。

**各項目の横にある矢印で、あるいはドラッグで並べ替えられる。** 一つのお金は一度しか使えないので、目標はリストの上から順に埋まっていく。上の目標が払い終わるまで下の目標は貯まり始めず、その待ち時間も達成日に含まれる。すでにある目標に入ったお金は動かない。新しい目標を一番上に置いても、古い目標がすでに受け取った分を取り上げることはない。

この日付は**働いている限り動かない**。稼ぎと時計は同じ速さで進むので、予定どおりに働けば約束は先送りされず守られる。ずらせるのは、その下にある勤務設定を変えたときだけ。休暇を入れる、勤務日を減らす、勤務時間を短くする、といった変更だ。

### メニューバー

| 項目                     | どうなるか                                                                       |
| ------------------------ | -------------------------------------------------------------------------------- |
| 進捗リング               | 金額の横に小さなリングが出て、一日をかけて満ちていく                             |
| 通貨記号                 | 表示と非表示を切り替える。1文字分の幅を買い戻せる                                |
| 勤務時間外はアイコンのみ | 金額が動いていない間は項目を畳む。夜、週末、出勤前                               |
| **金額を隠す**           | 時計が何を指していようと、戻すと言うまでメニューバーから金額を消す               |

**金額を隠す**はパネルの先頭項目でもあり、メニューバーから1クリックで届く。通話が始まるときや、肩越しにのぞかれているときのために。*すべて*を隠すことはない。リングは残る。そうしないと、金額を戻すためにクリックする対象がなくなってしまう。

### ログイン時に起動

アプリが `/Applications` から動いていることが条件。保存されるのは指定したとおりの状態だけで、トグルがオンなら起動時に自分を登録し、登録解除は一切しない。macOS は一度実行しただけのメニューバーアプリもログイン項目として並べてしまい、その答えはどちらに転んでも信用できないからだ。

## 金額の計算方法

```
basic per day     = basic salary ÷ (scheduled days − paid leave)
allowance per day = allowance    ÷ (scheduled days − all leave)
per second        = (basic per day + allowance per day) ÷ paid seconds per day
today             = paid seconds elapsed today × per second
this month        = days already earned × daily pay + today
```

どちらの除数も**実際の暦月**に対して数える。だから丸ごと働いた月はちょうど給与額に一致し、日額は月ごとに少しずつ動く。2026年8月の勤務日は21日、9月は22日、2027年2月は20日。

1日の有給時間は、出勤、退勤、休憩から求まる。「1日あたりの時間数」という別の入力欄は存在しないので、両者が食い違うことはあり得ない。

### ずれようがない

更新のたびに `(settings, now)` から計算し直し、**何も累積しない**。蓋を閉じる、スリープする、終了して起動し直す、システム時計を変える、時差のある土地へ飛ぶ。どれをやっても金額が狂うことはない。狂う対象になる累計値がそもそも無いからだ。

タイマーは「そろそろ再描画を」と言うだけ。数えてはいない。金額が止まっている間は20秒の居眠りまでペースを落とす。つまり、たいていの夜と、すべての週末がそうだ。

### 一時停止ボタンは、あえて無い

計算は有給時間帯の両端で張り付く。勤務開始の一瞬前は0、終了の一瞬後は1日分ちょうど。だから金額は**退勤後に自分で止まり、深夜0時に自分でリセットされる**。止めるべきタイマーもなければ、リセットすべき状態もない。

手動の一時停止は、ごく短い間だけ存在した。アプリで唯一の累積状態であり、最悪のバグ2件はどちらもそこから出た。一晩放置された一時停止は丸1日の勤務を超える分を差し引いて翌日をゼロにし、退勤後に始めた一時停止は確定したはずの当日合計を*逆向きに*刻ませた。この機能を削除したことで、この種類のバグがまるごと消えた。

## 既知の制限

- **夜勤（日をまたぐ勤務）は非対応。** 退勤は出勤より後でなければならない。そうでなければ、間違った金額を出す代わりに「設定が未完了」と表示する。
- **ボーナスは扱わない。** モデルにあるのは毎月固定の手当だけ。臨時の支給や年末の賞与をここに出すには1秒あたりの数字へ均す必要があり、それは実態を説明するというより金額を良く見せるだけだ。
- **税金も EPF も SOCSO もない。** どの数字も控除前の額面。
- **履歴は持たない。** 今月の累計は今月の勤務設定から導かれるもので、実際に働いた記録から出しているのではない。給与や勤務時間を変更すれば、今月のすでに過ぎた日も新しい単価で計算し直される。
- **勤務パターンは1つだけ。** 週単位で繰り返さないパターン、たとえば隔週の土曜出勤や交替制のシフトは、例外を手作業で入れる以外に表現できない。

## 開発

```bash
make                 # list every target
make test            # 268 tests
make install         # the Mac app, into /Applications
make run             # the iPhone app, on the simulator
```

フィーチャー優先のクリーンアーキテクチャで、レイヤーごとに SwiftPM ターゲットを1つ。依存の向きは規律ではなくコンパイラが強制する。設計上の判断、金額モデルの不変条件、そしてそれらを形づくったバグについては [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) に書いてある。
